Three hands-on drills for tuning an AI code reviewer. Pick a verifier vote threshold, label findings by severity, and measure how well a judge agrees with engineers. All data is synthetic and built for teaching.

Threshold tuner

The eval set has 30 confirmed bugs. The finders produced 50 candidate findings: 26 real bugs and 24 non-bugs. Four bugs were never found. Five verifier agents voted on each candidate. A finding is posted when it gets at least k "real" votes. A harmful FP is a non-bug posted as Important, which could push an agent author to break working code.

Severity triage

Label each finding as a calibrated reviewer would, then check your answer. Important means a bug to fix before merge. Nit means minor and non-blocking. Pre-existing means a real bug that this PR didn't introduce. Drop means it shouldn't be posted at all.

Agreement (Cohen's κ)

An LLM judge and a second engineer each labelled 12 reviewer findings as real bug or not a bug. Add your own labels, then compare. κ corrects raw agreement for chance: κ = (po − pe) / (1 − pe).
